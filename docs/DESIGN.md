# RÉSIVO — Design System

Rewritten 2026-10-18. This is the single source of truth for both surfaces:
the **staff desktop console** (PySide6/Qt 6) and the **student web portal** (Astro 5 + Tailwind v4).
Visual layer only — behaviour, data, auth, RLS, RPCs and workers are frozen.

Source of truth for tokens: `desktop/app/ui/theme.py` (desktop) and `web/src/styles/tokens.css` (web).
Never write a raw hex value, font size or shadow outside those two files.

---

## 1. Brand

Logo: `resivo_logo_transparent.png` (1254x1254, transparent, stacked layout: mark above wordmark).
Derived assets are generated by `tools/prepare_brand_assets.py` — never hand-edit them.

| Asset | Where | Use |
|---|---|---|
| `resivo_mark.png` | `desktop/assets/brand/`, `web/public/brand/` | icon only (R + building), tight crop, transparent |
| `resivo_logo.png` | same | mark + wordmark |
| `resivo_mark_white.png`, `resivo_logo_white.png` | same | all-opaque pixels forced white, alpha preserved |
| `resivo.ico` | `desktop/assets/brand/` | window icon (16/32/48/64/128/256) |
| `favicon.ico`, `favicon.svg`, `favicon-32.png` | `web/public/` | browser + app icon |

Rules
- White variants go on the navy sidebar and on the brand gradient. Full-colour mark goes on light surfaces.
- The **brand gradient** (`135deg`: navy-800 → teal-600 → green-500) is allowed **only** on: login/landing hero, the resident pass card, the 3px line at the top of the desktop sidebar, and the primary CTA on the landing hero. Never on body surfaces, cards, tables, or buttons.
- **Gold** (`gold-500`) is a premium accent only: resident pass, key highlight, active-nav marker, small decorative details. It is **never** text on white (fails contrast). Text/icon use of gold is allowed on navy backgrounds only.

## 3. Typography

Bundle locally, no CDN. OFL licences ship next to the files.

- **Outfit** 500/600/700 — headings, display, KPI numbers, the resident pass.
- **Inter** 400/500/600 — body, UI, tables, forms.
- Fallback stack: `"Segoe UI", system-ui, sans-serif`.

| Token | Size/line | Family + weight | Extra |
|---|---|---|---|
| `display` | 32/40 | Outfit 700 | -0.02em |
| `h1` | 24/32 | Outfit 600 | |
| `h2` | 18/26 | Outfit 600 | |
| `h3` | 15/22 | Inter 600 | |
| `body` | 14/22 | Inter 400 | |
| `small` | 12/18 | Inter 500 | |
| `overline` | 11/16 | Inter 600 | uppercase, +0.08em tracking |

- Tabular figures (`Inter` `tnum`) for card IDs, room numbers, counts, dates and every table numeric. Qt: `QFont.setFeature` when available, otherwise skip silently.
- Max paragraph width 70ch. Sentence case everywhere; uppercase only for overlines and table headers.

## 4. Shape, space, elevation, motion

- Spacing scale: 4 / 8 / 12 / 16 / 24 / 32 / 48.
- Radii: `8` inputs, buttons, badges · `12` cards, dialogs · `20` hero containers · `9999` pills.
- Borders: hairline 1px `border`. Elevation is minimal: `e1 = 0 1px 2px rgba(10,35,66,.06)`, `e2 = 0 8px 24px -8px rgba(10,35,66,.14)` (dialogs, popovers, toasts only).
  QSS has no `box-shadow`: cards at rest get a hairline border only; `QGraphicsDropShadowEffect` is used sparingly on dialogs, popovers and toasts.
- Motion: 150–200ms ease-out for hover, page transitions (fade/slide 8px), toasts and dialogs. Desktop: `QPropertyAnimation`. Web: CSS transitions + `prefers-reduced-motion: reduce` honoured. **Never animate table rows during live-sync redraw.**

## 7. Desktop shell

- Sidebar 248px, `navy-900`, 3px brand-gradient line at the very top, white logo mark + "RÉSIVO" wordmark + caption "Cité Universitaire · Tlemcen".
- Nav items 40px, icon + label, `text-on-dark-muted`; hover `#10305A`; **active** = `navy-800` background, white text, 2px `gold-500` marker on the left.
- Notification counters (pending applications, open tickets, pending transfers) = small gold-on-navy pills.
- Bottom: user card (avatar, name, role pill), sign-out ghost button, live-sync indicator (teal pulsing dot = connected, amber = reconnecting, red = offline) with tooltip.
- "Staff accounts" exists only for admin. Content area: canvas background, 32px padding, `PageHeader`, dense but airy.
- Login window: split layout. Left = gradient hero with large white logo, one value line, very low-opacity geometric pattern. Right = clean form (email, password, primary Sign in, inline error banner on failure, stays open on wrong credentials). Minimum 380x480 — hide the hero below 760px width.
- Window minimum 980x640. Resizing must never crush controls.

## 8. Web portal

Mobile-first; touch targets ≥ 44px; bottom tab bar on mobile, top nav on desktop.
Landing: gradient hero with white logo + Register/Log in CTAs, "How it works" 4 steps (Register › Verification › Room assigned › Live in residence), trust footer "Direction des Œuvres Universitaires · Cité Universitaire · Tlemcen".
Dashboard: state hero (pending amber / active green / rejected red with reason), digital resident pass for active students, maintenance tickets with category icons + stepper + photo dropzone, room-change form with locked banner for non-active students, profile split read-only vs editable.
Targets: Accessibility ≥ 95, no layout shift, fast LCP, self-hosted fonts.

## 9. Rules that must not break

Behaviour safeguards (both surfaces): pending applications cannot be deleted (disabled button + tooltip), rejection requires a non-empty reason, admin cannot delete own account (disabled + tooltip), transfer form locked for non-active students, desktop minimum window 980x640, splitter panels 340–480px, 2s live sync with differential redraw (never wipe filters/search), 3s bounded worker shutdown, photo viewer fit/zoom behaviour.

Accessibility: WCAG AA contrast on every text/background pair, keyboard navigation with visible focus, tooltips on every disabled action, sentence-case copy, no emoji.

## 10. Do / Don't

- **Do** use the token helpers; **don't** inline hex, px font sizes, or shadows in widgets/pages.
- **Do** pair every status colour with an icon and a text label; **don't** rely on colour alone.
- **Do** show empty states, loading skeletons and offline/error banners; **don't** leave blank areas.
- **Do** keep the same status vocabulary, icon names and component names across desktop and web.
- **Don't** use the brand gradient or gold outside the few places listed in §1.
- **Don't** add emojis, stock imagery, or decorative gradients.
